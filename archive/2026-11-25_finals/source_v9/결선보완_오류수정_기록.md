## M1. 객체가 아닌 JSON 을 받으면 서버가 죽음
- **원인**: `handle()` 이 `msg.get(...)` 를 바로 불렀다. 숫자·문자열·null·배치 안의 숫자가 오면 `AttributeError` 로 서버 프로세스가 종료돼 연결이 끊긴다. `method` 가 문자열이 아닐 때도 같다.
- **수정**(`app/hwpai/mcp.py`): 객체가 아니면 JSON-RPC -32600(잘못된 요청)으로 응답하고 계속 동작. 빈 배치도 -32600. 
- **시험**: `test_non_object_messages_do_not_kill_server`(제출본 코드에서 실패).

## M2. 한글 환경(파이썬 UTF-8 모드 아님)에서 서버가 죽음
- **원인**: `serve()` 가 `sys.stdin` 의 기본 인코딩을 썼다. 윈도 기본(cp949)에서 클라이언트가 보낸 UTF-8 한글 경로를 읽다 `UnicodeDecodeError` 로 종료(재현: `PYTHONUTF8=0 PYTHONIOENCODING=cp949`). 출력도 같은 기본 인코딩·윈도 `\r\n` 줄바꿈을 따른다. MCP 표준입출력은 UTF-8·줄 끝 `\n` 이다. `hwpai.bat`·`mcp-install` 은 `PYTHONUTF8=1` 을 주지만 Gemini·Codex 설정에 `python.exe` 만 적으면 빠진다.
- **수정**(`serve()` → `_utf8_stdio()`): 실제 표준입출력일 때 입력 UTF-8(깨진 바이트는 대체), 출력 UTF-8·줄 끝 `\n` 으로 맞춤. 시험에서 주입한 `stdin`·`stdout` 객체는 건드리지 않는다.
- **시험**: `test_utf8_stdio_without_python_utf8_mode`(제출본 코드에서 실패).
