# 웹판·앱판 QR 첫 실행 속도 개선 (2026-11-23, 커밋 a057eaf)

현장 QR(`demo.html`)로 처음 여는 휴대폰의 준비 시간을 줄였습니다. 기존 기능의 개선·보완입니다.

## 고친 것
1. 엔진 파일 8개를 하나씩 차례로 받던 것을 한꺼번에 받음(`js/engine.js`)
2. 처음 열 때 화면과 오프라인 저장(서비스 워커)이 같은 엔진 파일을 동시에 두 번 받던 것 → 오프라인 저장은 엔진 준비 뒤 시작, 이미 받은 파일을 옮겨 담음(`sw.js`, `js/pwa.js`)
3. 한 번 받은 엔진은 기기 저장소에 두고 SHA-256 확인 후 재사용, QR 입구는 저장본을 지우지 않음(`demo.html`)
4. 일꾼 여러 개가 동시에 뜨며 CPU를 나눠 쓰던 것 → 첫 일꾼을 먼저 올려 바로 시작
5. 예제 문서 미리 받기는 엔진 준비 뒤로

## 측정 (같은 조건: 휴대폰 화면, 회선 20Mbps로 제한한 시험 서버, CPU 2배 느리게)
| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 처음 방문, 엔진 준비까지 | 20.2초 | 11.5초 |
| 다시 방문, 엔진 준비까지 | 8.7초(10.9MB 다시 받음) | 3.6초(새로 받는 양 0) |

실서버(Pixel 7 흉내, 회선 제한 없음): 처음 6.2초에 준비, 예제 6건 14.3초, 정상 변환 6·개인정보 확인 1건, 오류 0.
실제 휴대폰·행사장 회선에서는 재지 않았습니다.

## 도구
- `srv2.js` — gzip·회선 속도 제한(공유 대역)·지연을 흉내 내는 시험 서버
- `m3.js` — 처음 방문·다시 방문의 엔진 준비 시간과 예제 처리 시간 측정(Playwright)
- `live.js` — 실서버 확인
